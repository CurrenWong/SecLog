### 关键经验（已固化到 MEMORY.md gotcha #10 + references/cloudbase-ai.md）
1. **服务端 SDK 用 `cloud.ai()`，不是 `cloud.extend.AI`**（后者是前端 API）
2. **wx-server-sdk 需 ≥3.x**（2.6.3 无 `cloud.ai()`，项目原本是 2.6.3，已升级 latest）
3. **云函数内网不要 `fetch + ApiKey`**（内网解析到内网地址 → 401；ApiKey 只给公网调试用，本地能过）
4. **ApiKey 频控误判**：短时高频请求触发临时 401（不是 key 失效），等 30s 恢复。用户给的 JWT key 长期有效，是我误判了
5. **前端 `wx.cloud.extend.AI` 的 content 只能 string，不支持多模态传图** → 识别必须走云函数，前端只做选图+上传+确认 UI

## 登录/个人中心 Bug 修复（晚 18:00）
- **现象**：头像/昵称能获取，但点保存提示"保存失败"。
- **根因**：`users` 集合默认安全规则是"仅创建者可读写"，依赖 `doc._openid == auth.openid`。但云函数服务端 `add` 写入的文档**不含 `_openid` 字段**（只有客户端 SDK 写入才自动带），导致后续 `update` 权限检查 `doc._openid == auth.openid` 失败 → SERVER_ERROR → 前端"保存失败"。
- **修复**：`managePermissions` 把 `users` 集合改为 `PRIVATE`（仅管理端/云函数可读写，客户端不可直接访问）。用户隔离仍靠 `where({openid})` 自己实现，不依赖 `_openid` 权限。云函数服务端写入不受安全规则约束。
- **顺带修 emoji 方框**：默认头像原本用 😊 emoji 占位，在 Windows 开发者工具/部分真机字体缺 emoji 时显示成方框。改为生成 `images/default-avatar.png`（PIL 画的浅蓝底+人形剪影），wxml 引用图片、去掉 emoji 分支。

## 保存失败真因（18:07 日志定位）
- **现象**：头像/昵称能获取，点保存提示 `SERVER_ERROR`。
- **真因**：`users` 集合**根本不存在**（`collection.get:fail -502005 database collection not exists`）。之前误判是权限问题（PRIVATE/ADMINWRITE 都试过），实际是集合未创建——`login` 的 add 也因集合不存在失败（没真正建集合）。
- **修复**：用 CloudBase MCP `writeNoSqlDatabaseStructure(action=createCollection, collectionName='users')` 建集合。
- **第二个坑**：`chooseAvatar` 返回 `wxfile://tmp_xxx.jpeg` 临时路径，直接存库会失效。改为 `onChooseAvatar` 里先 `wx.cloud.uploadFile` 到 `avatars/{openid}.png` 拿永久 `fileID` 再存；前端 image 组件直接支持 `cloud://` 路径显示。
- **定位手段**：前端 toast 显示 `res.result.code`（如 `SERVER_ERROR`），云函数 `console.log('[updateProfile] openid=...')`，再 `queryFunctions(listFunctionLogs → getFunctionLogDetail)` 看真实 RetMsg。
- **固化**：云函数用到新集合前，必须先用 MCP/控制台 createCollection，否则调用即 SERVER_ERROR。
