## SecLog 秒记小程序 — 记账/查询架构问题

### 当前架构（chatBot.js + agent-ui 组件）
- agent-ui 组件在用户发消息后，**无条件**调模型（index.js:1781，model 模式无跳过开关）
- chatBot.js 通过 `bind:userSend` 监听，在旁边额外做：记账(tryRecord) / 查询(tryQuery) / 撤回(tryUndo)
- 问题：记账场景 OK（✅ 卡片 + 模型轻量接话）；**查询场景模型自由发挥编造明细**（如"1280 + 6月假数据"）

### Curren 的核心反馈（重要）
> "模型应该先判断用户意图，然后根据意图选择合适的回复逻辑分支"

即：当前"前端监听 + 组件各自说话"是错的。应该是**单一意图判断入口 → 分流到确定逻辑（查库/记账/闲聊）**，模型只在"闲聊"分支才自由发挥，记账/查询分支由代码确定性地完成（不依赖模型编）。

### 待办（架构重构方向，未动手）
方案A：改 agent-ui 让 model 模式可不调模型，由 chatBot 统一接管"意图判断→分支"
方案B（更可行）：chatBot 拿到用户输入后，先做确定性意图路由（正则 parseQuery/parseUndo/parseExpense），
  若命中查询/记账/撤回 → **抑制 agent-ui 的模型回复**（需 agent-ui 支持"本次不调模型"开关），
  只插我们的确定性回复；只有"纯闲聊"才放行模型。
  难点：agent-ui 当前无"跳过模型"开关，需要加（如发消息时传 flag，或 chatBot 调用组件方法拦截）。
